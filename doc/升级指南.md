# 2.8.5.1-rc1 配套维护升级

本维护分支没有官方 v2.8.5 tag。common 使用历史提交 `3e64f2d7b022`，Boot 使用 `52187e6aa303`：已与正式仓下载的 2.8.5 制品核对平台属性，并独立编译核心类，核对标准化字节码。不能把此历史定位称为官方发布 tag，也不保证所有源文件均有可用的发布 sources 佐证。

## 平台与行为

common、eap-dependencies、eap-cloud-dependencies、Boot 必须配套使用 `2.8.5.1-rc1`。保留原 2.8.5 平台版本，不通过改版本号引入现代开发线：Spring Boot 3.5.3、Redisson 3.41.0、Netty 4.1.116.Final。jjwt-jackson 0.12.6 作为必要运行实现随 security 引入。

访问认证只接受 access token，refresh 只用于正常刷新端点。旧无 jti JWT 需要重新登录，历史别名缓存使用新的访问缓存命名空间隔离，不清空业务 Redis。依赖旧 refresh-as-access 行为的报表/WebSocket 调用方需持有有效 access 并正常刷新。同一应用的所有认证实例应协调切换，不能只回退一个实例重新开放旧语义。

## 隔离验证与发布边界

使用真实 JDK17，所有 Maven 命令指定独立 `-Dmaven.repo.local=<isolated-repository>`，不得覆盖共享缓存或已有制品。先安装两个独立 BOM，再执行 common 全量测试与安装，随后执行 Boot 全量测试、编译和安装。安装时保留 flatten，核对已安装坐标和父链，不将合法且已绑定的属性表达式误判为未解析版本。

测试 Redis 使用预先确认空闲的独立端口。完整测试中的既有短信时间夹具按 Asia/Shanghai，测试命令显式传 `-Duser.timezone=Asia/Shanghai`；这不改变应用运行时区。

通过 Boot 的 `script/verify-jwt-runtime/verify.py` 对实际打包依赖验证两种签名算法，不用测试库或编译器类填充运行 classpath。发布前记录源码提交、配套 GAV 与 POM/JAR 校验和；下游核对第三方依赖差异和正常 API 回归后再做部署验收。

本候选不授权公共 Maven 发布、环境部署或真实会话/业务数据操作。旧行为不得作为安全回滚；回滚需要整套配套考虑并重新登录，不能恢复已知错误用途认证。
