# 2.9.0.1-rc1 配套认证补丁升级指南

本候选从 v2.9.0 回移已确认的源头修复，不引入开发线的整套平台依赖升级。common、两个独立 BOM 和 boot 必须使用同一版本 2.9.0.1-rc1。

## 行为与迁移

- 每次 JWT 签发具有独立 jti，空 userKey 的旧调用不得产生相同会话令牌。
- 访问接口只接受 access token。refresh 只能通过正常刷新接口使用；积木报表、WebSocket 消费者需要持有有效 access token 并通过认证端刷新，不再依赖 refresh 冒充 Bearer。
- 旧无 jti JWT 要求重新登录；源生校验和撤销应拒绝歧义身份并处理关联刷新凭据。
- 同一应用的认证实例应协调切换，验证旧缓存污染不会继续认证；不要通过回滚恢复已确认的错误认证路径。
- 本候选不包含生产发布或历史业务数据迁移。

## 隔离构建与消费

使用真实 JDK 17，并通过 -Dmaven.repo.local=/private/tmp/eap-source-candidate/repository 指定隔离 Maven 仓。先安装两个独立 BOM，再执行 common 测试和安装，最后执行 boot 测试、编译和安装。

测试可用 -Dflatten.skip=true；安装时必须正常执行 flatten，核实安装 POM 没有未解析的 ${revision}。测试 Redis 仅使用本轮专用空闲端口，不连接业务 Redis。

下游先核 common、security、system、infra 的配套依赖树及第三方版本差异，再通过原生认证 API/Filter 覆盖签发、缓存/数据库认证、刷新和撤销。候选制品通过后才能移除应用层重复保护。
